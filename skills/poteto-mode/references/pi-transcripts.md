# Pi transcripts

Prefer the supplied parent transcript path or Pi session context. For the current session, use `PI_SESSION_FILE` when available. A child's environment names that child, not the original parent. Pass the parent's path and known identity to transcript readers explicitly.

Without a supplied path, search only this workspace's session candidates under `sessions/--<encoded-cwd>--/` in the Pi agent directory (`$PI_CODING_AGENT_DIR`, else `~/.pi/agent`). Encoding removes the leading separator and replaces `/`, `\`, and `:` with `-`. Verify the header's `cwd` and known session identity, such as the opening user prompt. Modification time orders candidates; it does not identify the parent. If identity cannot be established, report the gap or use a supplied digest. Never scan unrelated workspaces or the global session store.

Each `<timestamp>_<id>.jsonl` starts with a `type: "session"` header. Every later line is an entry with an `id` and a `parentId`. Message entries have `type: "message"` and `message.role` such as `user`, `assistant`, or `toolResult`. Entries form a tree, including abandoned branches. Follow `parentId` from the known active leaf and reverse that path, rather than treating every physical line or the last line as the active conversation. Pi session context exposes the active leaf and branch; if the leaf is unknown, establish the intended branch before drawing conclusions.

Follow relevant child transcript and output paths from actual launch receipts or status. Async receipts may expose `details.asyncDir`; a running child's transcript may be in `steps[0].sessionFile`, with top-level `sessionFile` and `outputFile` on completion. A child's `parentSession` identifies its immediate launcher. Do not assume a fixed artifact glob. Attributable artifacts may live outside the checkout; follow those paths without searching unrelated sessions or temporary files. Read only the task's selected history and sanitize private context before public output.
